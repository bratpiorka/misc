3. Practical Gap Summary
- The current safe UR layer covers context creation, queue creation, event recording/waiting, program loading, kernel wrappers, USM allocation, and both blocking and async copies.
- `UrEvent` now also exposes non-blocking status polling helpers, which is the closest counterpart to CUDA event query semantics.
- Program and kernel wrappers now live in the library instead of only in the example.
- A new async multi-GPU example now uses `UrEvent` to stage copies across two devices and chain kernels through event dependencies.
- `DeviceRepr` now exists for plain scalars, arrays, and user-defined `#[repr(C)]` structs passed as typed kernel arguments or used in host-to-device typed copies.
- The biggest remaining missing area relative to cudarc::driver is kernel launch ergonomics beyond the basic event-returning launch helper.
- Pointer traits now exist for whole allocations, but subview types and richer typed launch ergonomics are still missing.
- Context/device inspection is much thinner than cudarc.

4. Recommended Promotion Order
1	Queue launch builder and richer launch configuration
2	DevicePtr/DevicePtrMut-style traits
3	DeviceRepr-style trait for kernel argument and buffer typing
4	Context/device inspection helpers (ordinal, attribute, dedicated device/context accessors)
5	Device subview helpers
